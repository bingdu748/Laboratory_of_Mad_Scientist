# 05 · 运行方式

> 本项目如何在本地与 CI 环境运行。涉及 Token、依赖、脚本调用、测试、站点访问。

---

## 1. 前置条件

| 条件 | 说明 |
|------|------|
| Python 3.8+ | `generate_readme.yml` 使用 3.8；本地建议 3.8+ |
| Git | 拉取/推送仓库 |
| GitHub 仓库 | 作为内容存储（Issue = 文章）|
| GitHub Token | 需要 `repo` 权限的 Personal Access Token |
| pip | 安装 PyGithub |

---

## 2. 安装依赖

```bash
pip install -r requirements.txt
# 或
pip install PyGithub==1.59.1
```

---

## 3. 本地运行脚本（CLI）

以仓库根目录为工作目录运行（脚本已通过 `sys.path` 处理模块导入）。

### 3.1 生成文章 `posts/**/*.md`

处理**所有** Issue：

```bash
python scripts/generate_posts.py <GITHUB_TOKEN> <owner/repo>
```

只处理**指定** Issue：

```bash
python scripts/generate_posts.py <GITHUB_TOKEN> <owner/repo> --issue_number 17
```

> 注意：若指定的 Issue 已 `closed`，脚本会**删除**其对应的 `.md` 文件并清理空目录。

### 3.2 生成 README 与 RSS

```bash
python scripts/update_readme.py <GITHUB_TOKEN> <owner/repo>
```

生成/更新 `README.md`、`feed.xml`、`CHANGELOG.md`。

### 3.3 单独生成 JSON 导出与索引

引入模块直接调用函数：

```python
import sys
sys.path.insert(0, '.')
from scripts.generate_posts import export_json, generate_index_json
export_json('owner/repo')
generate_index_json()
```

## 4. 本地一键脚本（交互式）

> 仓库提供 `run_local.sh`（Linux/macOS）与 `run_local.bat`（Windows）。

```bash
bash scripts/run_local.sh
# 或 Windows 双击 bat
```

流程：检查 Python/pip → 安装依赖 → 交互式输入 Token 与仓库名 → 运行生成。

> ⚠️ 注意：`run_local.*` 内部调用的是历史遗留入口 `python main.py`，但当前仓库的入口脚本为 `generate_posts.py` / `update_readme.py`。如需使用本地脚本，建议改为直接调用下文 3.x 的命令。

## 5. 运行单元测试

用 Python 自带 `unittest` 运行：

```bash
# 在仓库根目录
python -m unittest scripts.test_utils -v
```

覆盖：PR/过滤逻辑、Markdown 清理、字数/图片统计、换行符归一化、跨平台一致性、快照测试。

## 6. CI 自动运行方式

默认不依赖本地运行，由 GitHub Actions 接管。

### 6.1 `generate_readme.yml`（主流水线）

触发条件：
- push 到 `master`（忽略 `README.md`/`feed.xml`/`posts/**`）
- Issue 事件（opened/edit/labeled/unlabeled/closed）
- 评论事件（created/edited/deleted）
- 定时：每天北京时间 22:15
- 手动 `workflow_dispatch`

步骤：安装依赖 → 单元测试 → 生成文章 → 生成 README/feed → 生成 JSON/索引 → commit + push。

### 6.2 `daily-squash.yml`（每日压缩）

- 定时：每天北京时间 23:30，或手动触发
- 把当天所有提交压缩成一条"每日提交汇总"，保持仓库历史整洁

### 6.3 `generate_site.yml`（站点部署）

- 在相应 `push` 或定时（23:40）后执行
- 用 `isite` + `zola` 构建，发布到 GitHub Pages

## 7. 运行产物核对

运行完成后，应生成/更新以下文件：

| 脚本 | 产物 |
|------|------|
| `generate_posts.py` | `posts/**/*.md`, `posts/index.json`, `posts_export.json`, `.temp_metadata.json` |
| `update_readme.py` | `README.md`, `feed.xml`, `CHANGELOG.md` |

## 8. 常见问题排查

| 问题 | 排查方向 |
|------|----------|
| 登录报错 401 | Token 失效或范围不足（需 `repo`）|
| 文章未出现在列表 | 检查 Issue 是否 open、字数 > 0 |
| 评论没进文章 | 该评论作者非当前登录用户（只有本人评论会被收录）|
| 字数与 GitHub 显示不一致 | 本项目按 CJK/英文/数字自定义口径统计 |
| rebase 冲突 | 生成产物走 `merge=ours`；手写代码冲突需人工解决 |
| push 被拒绝 (fetch first) | 先 `git pull --rebase` 或按仓库约定处理 |
