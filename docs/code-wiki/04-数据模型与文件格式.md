# 04 · 数据模型与文件格式

> 说明各类产物文件的数据结构与字段含义，帮助理解数据流转。

---

## 1. 数据流一览

```
GitHub Issues/Labels/Comments/PRs
        │  generate_posts.py
        ├──→ posts/<label>/<safe_title>.md   （文章）
        ├──→ posts_export.json               （全量导出）
        ├──→ posts/index.json                （目录索引）
        ├──→ .temp_metadata.json             （字/图统计缓存）
        │
        │  update_readme.py
        ├──→ README.md
        ├──→ feed.xml
        └──→ CHANGELOG.md
```

**元数据缓存（`.temp_metadata.json`）** 是桥梁：`generate_posts` 在生成文章时顺带写入（含评论的字/图统计），`update_readme` 读它来避免重复发 API 统计。

---

## 2. `.temp_metadata.json` — 统计元数据缓存

**生成者**：`save_issue()`。**字段结构**（key 为 issue number 字符串）：

```json
{
  "16": {
    "title": "「Diary」2006 & 2007",
    "filename": "Diary2006..2007",
    "label": "my-diary",
    "updated": "2026-06-16T09:48:32+00:00",
    "word_count": 2067,
    "image_count": 0
  },
  ...
}
```

| 字段 | 类型 | 含义 |
|------|------|------|
| key | str | Issue 编号 |
| `title` | str | Issue 标题 |
| `filename` | str | sanitize 后的文件名（不含 .md） |
| `label` | str | 标签目录名（无标签为 `no-label`） |
| `updated` | str | 更新时间（ISO8601）|
| `word_count` | int | 全文（含评论）字数 |
| `image_count` | int | 全文图片数 |

---

## 3. `posts/<label>/<safe_title>.md` — 文章文件

**生成者**：`save_issue()`。

文件名规则：`sanitize_filename(issue.title)`（`/`、`\` → `-`，空格 → `.`，仅保留字母数字与 `.-_`）。

**内容结构**：

```markdown
<!--
  issue_number: 17
  state: open
  created_at: 2026-06-16T09:36:14+00:00
  updated_at: 2026-06-16T09:36:14+00:00
  labels: [my-diary]
  url: https://github.com/volatile-Quartz/Dr_Wunderkammer/issues/17
-->

# [「Diary」2014](https://github.com/volatile-Quartz/Dr_Wunderkammer/issues/17)

## 文档说明

存放2014年的日记。
待整理..

## <评论标题或时间戳>

<评论正文，标题已降一级>
```

| 段落 | 来源 |
|------|------|
| 头部 `<!-- -->` 注释块 | Issue 元数据（机器可读，渲染时不可见） |
| H1 标题 | Issue 标题，链接回原文 |
| `## 文档说明` | Issue 正文 `body` |
| `## <标题>`（若干） | Issue 的**作者本人评论**，按时间排序，每个评论一段 |

## 4. `posts/index.json` — 目录索引

**生成者**：`generate_index_json()`。

```json
{
  "generated_at": "2026-08-31T05:44:41.656431+00:00",
  "entries": [
    {
      "path": "the-lore/About.Calculations.md",
      "title": "About.Calculations.md",
      "label": "the-lore",
      "word_count": 113,
      "image_count": 0,
      "file_size": 647,
      "sha256_short": "e6e9bf67b8d6ee7a"
    }
  ],
  "total_files": 18
}
```

| 字段 | 类型 | 含义 |
|------|------|------|
| `generated_at` | ISO 时间 | 生成时间 |
| `entries[].path` | str | 相对 `posts/` 的路径 |
| `entries[].title` | str | 文件 H1 标题（缺失时回退为文件名） |
| `entries[].label` | str | 目录名（根目录为 `root`） |
| `entries[].word_count` / `image_count` | int | 该文件统计 |
| `entries[].file_size` | int | UTF-8 编码后字节数 |
| `entries[].sha256_short` | str | 内容 SHA256 前 16 位（完整性校验） |
| `total_files` | int | 文件总数 |

## 5. `posts_export.json` — 全量导出

**生成者**：`export_json(repo_name)`。

```json
{
  "repository": "owner/repo",
  "generated_at": "2026-…",
  "total_issues": 16,
  "issues": [
    {
      "issue_number": 1,
      "title": "About Diary",
      "filename": "About.Diary",
      "label": "the-lore",
      "updated": "…",
      "word_count": 57,
      "image_count": 0,
      "md_path": "posts/the-lore/About.Diary.md",
      "url": "https://github.com/owner/repo/issues/1",
      "content": "…(对应 .md 全文)…"
    }
  ]
}
```

| 字段 | 含义 |
|------|------|
| `repository` / `generated_at` / `total_issues` | 顶层信息 |
| `issues[]` | 按 issue number 升序排列 |
| `md_path` | 对应 `.md` 相对路径 |
| `url` | issue 原文链接 |
| `content` | 对应 `.md` 全文内容（便于程序化处理与迁移） |

## 6. `README.md` — 门户首页

**生成者**：`regenerate_readme()`。

结构（内存拼装）：

```markdown
> 记录自我，留存活过的痕迹。
> ...

## 置顶文章        ← add_md_top     （标签含 Top/置顶）
## 待办事项        ← add_md_todo    （标签含 TODO/待办）
## my-diary       ← add_md_label   （每标签一个 ## + issue 列表）
## the-lore
## 文章列表        ← add_md_recent  （Markdown 表格）

## 博客统计
- 最后更新: YYYY-MM-DD HH:MM:SS
- 总文章数: N
- 新增文章: N     （最近24h 创建的）
- 更新文章: N     （最近24h 更新的）
- 总字数: N
- 总插图数: N
```

## 7. `feed.xml` — RSS 订阅

**生成者**：`generate_rss_feed()`。

RSS 2.0 格式，最多 `RECENT_ISSUE_LIMIT`（20）条，按更新时间倒序，仅含本人非 PR issue。

```xml
<?xml version="1.0" encoding="UTF-8"?>
<rss version="2.0">
  <channel>
    <title>{repo.name} Blog</title>
    <link>{repo.html_url}</link>
    <description>Blog generated from GitHub issues</description>
    <language>zh-CN</language>
    <lastBuildDate>...</lastBuildDate>
    <item>
      <title>...</title>
      <link>...</link>
      <description>前200字符+...</description>
      <pubDate>...</pubDate>
      <guid>...</guid>
    </item>
  </channel>
</rss>
```

## 8. `CHANGELOG.md` — 第三方 PR 记录

**生成者**：`generate_changelog()`。

只统计**非本人**的 Pull Request（如 Dependabot 升级），最多 20 条：

```markdown
# 更新日志

| PR 标题 | 链接 | 更新时间 |
|:--------|:-----|:--------|
| Bump actions/checkout from 6 to 7 ... | [PR #29](https://github.com/…/pull/29) | 2026-07-22 00:34 |
```

---

## 9. 字数与图片统计口径

| 统计内容 | 规则 |
|----------|------|
| 中文字数 | CJK 字符（汉字 + CJK 标点 `\u3001-\u303f`、全角 `\uff00-\uffef`）逐字计 |
| 英文字数 | 每个英文单词（`[a-zA-Z]+`）计 1 |
| 数字 | 每个独立数字串（`\d+`）计 1 |
| 图片 | MD `![]()` + HTML `<img>` 均计入 |
| 统计范围优先级 | `.md` 文件（含评论）> 元数据缓存 > Issue body（无评论）|
| 换行符 | 一律先归一化为 `\n` 再统计，保证跨平台一致 |

## 10. `.gitattributes` — 冲突策略

```ini
# merge=ours：自动生成文件冲突时始终采用当前分支版本
README.md merge=ours
feed.xml merge=ours
CHANGELOG.md merge=ours
.temp_metadata.json merge=ours
posts_export.json merge=ours
posts/index.json merge=ours
```

**作用**：在工作流发生 rebase 冲突或 merge 时，这些自动生成的产物不会被对方的旧版本覆盖，永远保留"当前（本地）新生成"的版本。真正的手写代码（`scripts/**`）不在其中，冲突仍需人工处理。
