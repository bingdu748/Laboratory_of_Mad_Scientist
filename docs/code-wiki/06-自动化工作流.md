# 06 · 自动化工作流

> 详解 `.github/workflows/` 下三个 GitHub Actions 工作流：配置、触发、核心步骤、并发互斥、Git 冲突处理策略。

---

## 0. 总览

| 工作流 | 文件 | 每日定时(北京) | 主要职责 |
|--------|------|----------------|----------|
| Generate README | `generate_readme.yml` | 22:15 | 拉取 Issue → 生成全部产物 → commit/push |
| Daily Commit Squash | `daily-squash.yml` | 23:30 | 把当天提交压缩成一条汇总 |
| Deploy to Pages | `generate_site.yml` | 23:40 | isite+zola 构建并部署 Pages |

三者通过 **`concurrency.group: master-branch-write`** 互斥：同一时间只允许一个实例写 master，新触发会 `cancel-in-progress`。

---

## 1. `generate_readme.yml` — 主流水线

### 1.1 触发条件

| 触发 | 说明 |
|------|------|
| `issues` | opened / edited / labeled / unlabeled / closed |
| `issue_comment` | created / edited / deleted |
| `push` | 仅 `master` 分支，`paths-ignore` 忽略 `README.md`、`feed.xml`、`posts/**` |
| `schedule` | cron `15 14 * * *`（UTC 14:15 = 北京 22:15）|
| `workflow_dispatch` | 手动 |

### 1.2 环境与并发

```yaml
concurrency:
  group: master-branch-write
  cancel-in-progress: true

env:
  FORCE_JAVASCRIPT_ACTIONS_TO_NODE24: true
  TZ: Asia/Shanghai
```

### 1.3 步骤流水线

```
1. Checkout           actions/checkout@v6   fetch-depth:0, GITHUB_TOKEN
2. Setup Python       3.8
3. Install deps       pip install PyGithub
4. Run unit tests     python -m unittest scripts.test_utils -v
5. Generate posts     （非 schedule 时执行）
     - issue 事件 → 只处理对应 --issue_number
     - 其他 → 处理全部
6. Generate README    python scripts/update_readme.py <token> <repo>
7. Generate JSON      export_json() + generate_index_json()
8. Commit and push    一次提交所有变更
```

### 1.4 步骤 5（生成 posts）关键逻辑

```bash
ISSUE_NUMBER=""
if [ event == issues 或 issue_comment ]; then
  ISSUE_NUMBER=github.event.issue.number
fi
if [ -n "$ISSUE_NUMBER" ]; then
  python scripts/generate_posts.py ... --issue_number $ISSUE_NUMBER
else
  python scripts/generate_posts.py ...        # 全部
fi
```

> schedule 触发时跳过此步（只更新 README/feed）。

### 1.5 步骤 8（Commit and push）关键逻辑

负责合并多个机器生成的提交为一个干净提交，**核心保护逻辑**：

1. **无变更检查**：`git diff --cached` 为空 → 跳过提交
2. **配置 merge driver**：
   ```bash
   git config merge.ours.driver 'git merge-file --ours %A %O %B'
   ```
3. **时间戳拦截**：遍历暂存文件，若 README/feed/export/index **仅改动 ≤2 行**（视为时间戳微调），则 `git reset --hard HEAD` 放弃提交而不报错；否则标记为实质变更继续。
4. **stash 无关变更**：`git stash push --keep-index --include-untracked`
5. **提交**：`git commit -m "Auto-update: YYYY-MM-DD"`
6. **rebase**：`git fetch` + `git rebase origin/master`
   - 失败则 `--abort` → `git merge origin/master -X ours`（保留本地生成版本）
7. **恢复 stash**：`git stash pop`
8. **推送**：`git push origin HEAD:master`

## 2. `daily-squash.yml` — 每日提交压缩

### 2.1 触发

- `schedule`: cron `30 15 * * *`（UTC 15:30 = 北京 23:30），在 generate（22:15）之后
- `workflow_dispatch`：手动

- 与 generate_readme 共享 `concurrency.group: master-branch-write` 互斥

### 2.2 步骤

```
1. Checkout    actions/checkout@v6   fetch-depth:0（需完整历史）
2. Configure   git config user.email/name
3. Locate      找最近"每日提交汇总"提交作为锚点
               git log --grep="每日提交汇总"
4. Count       锚点后的提交数 commit_count
5. Squash      若 commit_count>0 → git reset --soft 锚点 → git add -A → commit "今日 - 每日提交汇总"
6. No commits  若为 0 → 跳过
7. Safe push   fetch → 落后则 merge -X ours → git push --force-with-lease
```

### 2.3 关键点

- 用 `git reset --soft` 重写历史：锚点之后全部变更进入暂存区，再一次性提交为汇总，避免逐条 rebase 冲突。
- 推送用 **`--force-with-lease`**（安全强制推送），避免覆盖他人无意之外的提交。

## 3. `generate_site.yml` — GitHub Pages 部署

### 3.1 触发

| 触发 | 说明 |
|------|------|
| `push` | `main` / `master`，paths 包括 `README.md`/`feed.xml`/`posts/**`/`.temp_metadata.json`/`posts_export.json`/`CHANGELOG.md` |
| `schedule` | cron `40 15 * * *`（UTC 15:40 = 北京 23:40），在 squash 之后兜底重建 |
| `workflow_dispatch` | 手动 |

### 3.2 权限

```yaml
permissions:
  contents: read
  pages: write
  id-token: write
concurrency:
  group: ${{ github.workflow }}   # 独立于 master-branch-write
```

### 3.3 步骤

```
1. Checkout
2. Set repo/base url   REPO、BASE_URL=https://owner.github.io/REPO
3. Generate markdown
     - gh release download isite v0.2.2 (kemingy/isite) → 解压到 /usr/local/bin
     - isite generate --user $USER --repo $REPO    → output/ 目录
     - gh release download zola v0.20.0 (getzola/zola) → /usr/local/bin
     - cd output && zola build --base-url "$BASE_URL"
4. Setup Pages         actions/configure-pages@v6
5. Upload artifact     actions/upload-pages-artifact@v5  path: 'output/public'
6. Deploy              actions/deploy-pages@v5
```

- `GH_TOKEN: ${{ github.token }}` 供 gh CLI 下载 release。
- 产物目录为 `output/public/`。

## 4. 互斥锁与执行时序（北京时间日循环）

```
 22:15   generate_readme.yml  （master-branch-write）
   │        拉取→生成→推送
 23:30   daily-squash.yml      （master-branch-write，抢锁）
   │        压缩当天提交
 23:40   generate_site.yml     （独立 concurrency 组）
            构建并部署 Pages
```

> `cancel-in-progress: true` 确保新触发的写 master 任务会取消仍在运行的旧写任务，防止并发写导致的互相覆盖 / 冲突。

## 5. 冲突处理策略汇总

| 场景 | 策略 | 位置 |
|------|------|------|
| 生成产物冲突 | `.gitattributes` `merge=ours`，使用当前/本地版本 | 全局 |
| rebase 冲突（读 master）| `git rebase --abort` → `git merge -X ours` | generate_readme step 8 |
| squash 前落后远程 | `git merge origin/master -X ours` | daily-squash step 7 |
| 压缩推送 | `git push --force-with-lease`（仅 Daily） | daily-squash step 7 |
| 仅时间戳变化 | `git reset --hard HEAD` 跳过提交 | generate_readme step 8 |

## 6. 手动触发与观察

- 手动触发：GitHub 仓库 → **Actions** 页 → 对应工作流 → **Run workflow**。
- 观察执行：Actions → 展开 job → 查看各个 step 输出（均有中文日志）。
- 失败排查：优先看 step 报错，常见于网络下载 isite/zola、token 权限、rebase 冲突。
