## 1. `scripts/utils.py` — 公共工具模块

### 1.1 日志与环境

#### `log_environment()`

- **位置**：`scripts/utils.py`
- **职责**：打印当前运行环境信息（平台、Python 版本、CI 标志、事件名、工作目录、编码），以 JSON 单行输出到日志，用于跨环境调试。

### 1.2 GitHub 认证与身份

#### `login(token)`

- **位置**：`scripts/utils.py`
- **参数**：`token` (str) — GitHub Personal Access Token
- **返回**：`github.Github` 客户端实例
- **职责**：初始化 PyGithub 客户端。优先用新版 `github.Auth.Token(token)` 方式认证，旧版本回退到直接传 token 的构造器。

#### `get_repo(user, repo_name)`

- **位置**：`scripts/utils.py`
- **参数**：`user` (github.Github), `repo_name` (str, `owner/repo`)
- **返回**：`github.Repository` 实例

#### `get_me(user)`

- **位置**：`scripts/utils.py`
- **返回**：用户名（str）
- **职责**：区分 CI 环境与本地：
  - CI 中优先用 `GITHUB_ACTOR` → 其次解析 `GITHUB_REPOSITORY` 的 owner → 默认 `"github-actions"`
  - 本地调用 `user.get_user().login`

#### `is_me(issue_or_comment, me)`

- **位置**：`scripts/utils.py`
- **参数**：`issue_or_comment`, `me` (str)
- **返回**：bool — 比较 `.user.login` 与 `me`

### 1.3 时间格式化

#### `format_time(time_obj)`

- **位置**：`scripts/utils.py`
- **参数**：datetime 对象（可能无时区）
- **返回**：`"YYYY-MM-DD HH:MM"` 格式字符串（北京时间）
- **职责**：无 `tzinfo` 则先赋 UTC，再 `astimezone` 到 `BEIJING_TZ`。

### 1.4 Markdown 清理与统计

#### `_normalize_line_endings(text)` → str

- **职责**：`\r\n` → `\n`，`\r` → `\n`，确保跨平台文本一致。

#### `_clean_markdown(text)` → str

- **职责**：把 Markdown 转为纯文本，用于统计真正的"显示字数"。清理项包括：
  - HTML 注释、代码块（``` 或 ~~~）、行内代码
  - 图片 `![...](...)`（**连 alt 文本一起去掉**）
  - 链接转文本：`[text](url)` → `text`
  - HTML 标签、裸 URL、表格分隔线
  - 引用 `>`、列表 `-` / `*` / `+`
  - 标题 `#`
  - 加粗 `**`、斜体 `*`、下划线 `__`、删除线 `~~`
  - 管道符 `|` → 空格、反斜杠转义
  - 合并多余空白

#### `_count_words(clean_text)` → int

- **职责**：统计三类的数量之和：
  - 中文汉字 + 中文标点 (`\u4e00-\u9fff`, `\u3000-\u303f`, `\uff00-\uffef`)
  - 英文单词 (`[a-zA-Z]+`)
  - 数字 (`\d+`)

#### `get_content_word_count(content)` → int

- **职责**：组合 `_clean_markdown` + `_count_words`，封装错误处理。

#### `get_content_image_count(content)` → int

- **职责**：正则统计 Markdown 图片 `![]()` + HTML `<img>` 标签数量。

#### `get_issue_word_count(issue)` → int

- **职责**：仅统计 `issue.body`（不含评论），用于无元数据时的回退。

#### `get_issue_image_count(issue)` → int

- **职责**：仅统计 `issue.body` 中的图片数量。

### 1.5 过滤逻辑

#### `is_pull_request(issue)` → bool

- **职责**：检查 `issue.pull_request is not None`。异常时返回 `False`。

#### `should_include_issue(issue, metadata=None)` → bool

- **职责**：判断一篇文章是否应出现在博客列表中。四个条件**全部**满足才为 `True`：
  1. 不是 Pull Request
  2. `state == "open"`
  3. `word_count > 0`（优先从元数据读取，否则回退到 `issue.body`）
  4. `image_count >= 0`

- **优先级**：元数据 > `issue.body`。如果元数据存在且 `word_count` 键存在，就用它。

### 1.6 元数据操作

#### `load_metadata()` → dict

- **职责**：读取 `.temp_metadata.json`，返回 `{issue_number: {...}}`，文件不存在返回 `{}`。

#### `save_metadata(metadata)`

- **职责**：把字典写回 `.temp_metadata.json`。

### 1.7 回退统计

#### `count_from_md_file(issue_number, issue_title)` → `(int, int) | (None, None)`

- **职责**：通过已生成的 `posts/**/<safe_title>.md` 文件统计字数和图片数。在 `update_readme.py` 中作为三层回退的**第一层**使用。

## 2. `scripts/generate_posts.py` — 文章生成模块

### 2.1 Issue 获取

#### `get_to_generate_issues(repo, me, issue_number=None)` → list

- **职责**：
  - 指定了 `issue_number`：返回单元素列表（`repo.get_issue()`）
  - 未指定：返回全部 `repo.get_issues()`

### 2.2 文件名与目录

#### `sanitize_filename(title)` → str

- **职责**：`/` `\` → `-`，空格 → `.`，只保留字母数字和 `.-_`。

#### `get_label_dir(issue)` → str

- **职责**：取 Issue 标签中**第一个**不在 `IGNORE_LABELS` 里的标签名；没有则返回 `"no-label"`。

### 2.3 评论处理

#### `_extract_comment_title_and_body(comment, me)` → `(title, body)`

- **职责**：
  - 如果评论首行是 `# ` 一级标题：提取为 `title`，其余内容通过 `_downgrade_headings` 标题降一级
  - 否则：`title` 为评论创建时间的格式化字符串，`body` 为全部内容降一级

#### `_downgrade_headings(text)` → str

- **职责**：正则 `^(#{1,6})(?=\s)` → `#\1`，即 `#` → `##`，`##` → `###` ……避免与文章本身的一级标题冲突。

### 2.4 核心：保存 Issue

#### `save_issue(issue, me)` → str (文件路径)

- **职责**：
  1. 确定 `label_dir`，创建目录
  2. 以 `sanitize_filename(issue.title).md` 为文件名打开写
  3. 写入内容结构：
     ```markdown
     <!-- 元数据注释块 -->
     # [Issue Title](html_url)

     ## 文档说明

     (issue.body)

     ## (评论标题 或 时间戳)

     (评论正文，标题已降级)

     ...
     ```
  4. 读回完整文件，统计 `word_count` + `image_count`
  5. 写 `.temp_metadata.json` 缓存

#### `delete_issue_files(issue)`

- **职责**：Issue 被关闭时删除对应的 `.md` 文件。先在元数据中查找，再遍历 `posts/` 目录兜底。

#### `cleanup_empty_dirs()`

- **职责**：自底向上遍历 `posts/`，删除空目录。

### 2.5 导出与索引

#### `export_json(repo_name)`

- **职责**：遍历元数据，把每个 issue 的信息 + 正文内容写入 `posts_export.json`，字段包括 `issue_number`, `title`, `label`, `md_path`, `content` 等。

#### `generate_index_json()`

- **职责**：遍历 `posts/` 下所有 `.md`，提取 H1 标题、字数、图片数、文件大小、SHA256（前 16 位），生成 `posts/index.json`。

### 2.6 主入口

#### `main()`

- **CLI 参数**：`token`, `repo_name`, `--issue_number`（可选）
- **流程**：
  1. 登录 → 获取仓库
  2. 若指定 issue 且已关闭 → 删除文件 + 清理空目录 → 结束
  3. 否则获取全部 issues → 仅处理本人 issue → `save_issue`
  4. 清理空目录 → `export_json` → `generate_index_json`

## 3. `scripts/update_readme.py` — README / RSS 更新模块

### 3.1 辅助

#### `_has_label(issue, labels)` → bool

- **职责**：判断 Issue 是否包含给定标签列表中任意一个。

#### `_add_issue_line(issue)` → str

- **返回**：Markdown 列表项 `- [title](url)--YYYY-MM-DD HH:MM`

### 3.2 区块生成

| 函数 | 输入 | 输出 |
|------|------|------|
| `add_md_todo(all_issues, me)` | 全部 issues | 待办事项 Markdown 块（标题过滤 `TODO` 标签） |
| `add_md_top(all_issues, me)` | 全部 issues | 置顶文章 Markdown 块（标题过滤 `Top` 标签） |
| `add_md_recent(all_issues, me, limit=20)` | 全部 issues | 表格形式的文章列表（序号/标题/时间/字数/图片） |
| `add_md_label(all_issues, labels, me)` | 全部 issues + 全部 labels | 按标签分类的文章列表区块 |

**`add_md_recent` 的三层回退统计**（按优先级）：
1. 读已生成的 `.md` 文件 → `count_from_md_file`
2. `.temp_metadata.json` 缓存
3. 回退到 `issue.body`（不含评论）

### 3.3 独立文件生成

#### `generate_changelog(all_issues, me)`

- **职责**：筛选"非本人的 PR" → 按时间倒序写入 `CHANGELOG.md`。

#### `generate_rss_feed(all_issues, repo, me)`

- **职责**：生成 RSS 2.0 格式的 `feed.xml`，取最近 20 篇 Issue。

#### `ensure_readme_exists()`

- **职责**：`README.md` 不存在时创建一个默认空壳，防止后续读写报错。

### 3.4 核心：重新生成 README

#### `regenerate_readme(repo, repo_name, me)` → list (issues)

- **职责**：
  1. 一次性拉取 `repo.get_issues(state='all')` + `repo.get_labels()`
  2. 在内存按顺序拼装：开头引言 → `add_md_top` → `add_md_todo` → `add_md_label` → `add_md_recent` → 统计区块
  3. 生成 `CHANGELOG.md`
  4. 统计信息：总文章数、总字数、总插图、最近 24h 新增/更新
  5. **与现有文件内容对比**，相同则跳过写入
  6. 返回全部 issues 供 RSS 复用

### 3.5 主入口

#### `main()`

- **CLI 参数**：`token`, `repo_name`
- **流程**：登录 → `ensure_readme_exists()` → `regenerate_readme()` → `generate_rss_feed()`
